# filmotiv-media — независимый видео-прокси Filmotiv для Render

Выносит стриминговый прокси `/api/media` с Vercel (лимит Fast Origin Transfer
10 ГБ/мес, проект ставится на паузу при 100%) на Render free: **100 ГБ/мес
исходящего трафика, без карты, без телефона**.

Внутри — байт-в-байт копия продового хендлера `api/media/[...url].mjs`
Filmotiv **v211** (hang-protection: таймаут старта ответа 12 с + одна
авто-повторка + разрыв апстрима при уходе клиента) + тонкая обёртка
`node:http` с диагностикой. Проект полностью независим: ни общих сервисов,
ни общих аккаунтов с Genopoisk.

## ⚠️ Требование: ОТДЕЛЬНЫЙ Render-аккаунт

Лимит Render free — **750 инстанс-часов в месяц НА АККАУНТ**, а не на сервис.
Keepalive держит сервис бодрым ~730 ч/мес, поэтому два всегда-тёплых
бесплатных сервиса на одном аккаунте не помещаются. Этот сервис обязан жить
на **втором аккаунте Render (другой email)** — там будет свой чистый бюджет
750 ч. Заводить keepalive-прокси на аккаунте, где уже живёт другой
keepalive-сервис, нельзя: бюджет кончится посреди месяца и лягут оба.

## Развернуть (≈2 минуты, с телефона)

1. Зарегистрировать **новый аккаунт** на dashboard.render.com (другой email,
   не тот, где genopoisk-media).
2. Кнопка **New +** (сверху справа) → **Web Service**.
3. Внизу страницы выбрать вкладку **Public Git repository** (GitHub
   подключать НЕ нужно, просто вставить ссылку):
   ```
   https://github.com/Genocide12/filmotiv-media
   ```
4. Заполнить форму:
   - **Name**: `filmotiv-media`
   - **Region**: `Frankfurt (EU Central)` — ближайший к РФ, для этого CDN
     egress через Frankfurt уже подтверждён (замер 2026-10-07)
   - **Branch**: `main` (по умолчанию)
   - **Build Command**: оставить `npm install` (зависимостей нет — мгновенно)
   - **Start Command**: `node media-server.mjs`
   - **Instance Type**: **Free**
   - Переменные окружения НЕ нужны (никаких секретов).
5. Нажать **Deploy Web Service** — сборка ~1 минута.
6. Когда статус станет **Live**: **Settings → Render Subdomain** — убедиться,
   что адрес в точности `https://filmotiv-media.onrender.com` (без суффиксов).
   Если имя занято и Render добавил суффикс — сменить subdomain на
   `filmotiv-media` или сообщить фактический адрес: от него зависит keepalive
   и переключение прода.
7. **Прислать итоговый адрес** — дальше всё автоматически: решающий тест
   egress, переключение прода одним коммитом, мониторинг.

## Почему решающий тест нужен

ВидеCDN отдаёт сегменты не всем IP (замер 25.09.2026: AWS us-east-1 → 200,
Vercel edge → 410, домашние РФ → 410). Render работает на AWS, но конкретный
egress-IP нового сервиса нужно проверить — тест занимает 1 минуту и делается
без вас.

Если тест скажет `BLOCKED`:
- **Settings → Delete service** и создать заново теми же шагами, но с
  регионом **Ohio (US East)**, затем `Oregon`, затем `Singapore`.
- Каждый вариант проверяется за минуту. Если не подошёл ни один — в Render
  нужного региона нет, вернёмся к альтернативам (пакет переносится куда
  угодно, это 2 файла).

## Что уже встроено

| Файл | Назначение |
|---|---|
| `media-handler.mjs` | копия продового прокси Filmotiv v211 (не изменять) |
| `media-server.mjs` | обёртка: `/api/media/…`, `/health`, `/egress/status`, `/egress/test?url=` |
| `.github/workflows/keepalive.yml` | пинг каждые 10 мин (публичный репо = бесплатные минуты Actions) — free-сервис Render не засыпает; URL вписан реальный |

## Эндпоинты после деплоя

- `GET /health` → `{"ok":true,...}` — живость + keep-alive
- `GET /egress/status` — отвечает ли CDN этому egress вообще (410 на корне — норма)
- `GET /egress/test?url=<сегмент>` — вердикт по живому сегменту
  (URL сегмента берётся из devtools плеера; tokens одноразовые)
- `GET /api/media/<enc>` — сам прокси, та же схема URL, что на Vercel

## Лимиты Render free (учтено)

- 100 ГБ/мес трафика на этот аккаунт — ожидаемое потребление порядка
  15–20 ГБ/мес, запас ~5×; мониторить дашборд Render
- 750 инстанс-часов/мес на этот аккаунт — keepalive занимает ~730 ч,
  сервис бодрый 24/7, холодных стартов у зрителей нет
- 512 МБ RAM — прокси стримит без буферизации, хватает
- засыпание через 15 мин простоя — закрыто пингом каждые 10 мин
